# Sit with Haven

A mobile-friendly property-management MVP prototype for Disiplina Village Valenzuela City. It starts with 22 buildings and 792 units, supports up to 150 buildings with 36 units per building, and provides distinct Property Management and Association Management environments. Property Management includes Building, Commercial, SFR (single-family rental), and MFR (multifamily rental) profiles; association, property/unit, tenant, and homeowner dashboard previews; structured property profile sections; customizable property groups; universal search; profile-menu access to personal and administrator settings; bulk rent updates; a property-scoped unit directory with manual and CSV entry; manual tenant and household member records; pet details; recurring charges; a rent ledger and receipts; payment instructions; maintenance conversations; shared-space requests; violations; centralized individual and custom consolidated reports; notification preferences; and staff contact registration.

## Launch readiness

**Demo prototype only — not ready for actual resident, owner, or payment data.** Records live in browser `localStorage`, with no authenticated accounts, secure server, shared database, backups, tenant isolation, or server-enforced permissions. Demo-role controls are client-side previews and are not security controls. Payment processing, email/SMS delivery, and production monitoring are not configured. Do not publish this demo for real operations or enter personal or financial information. A production launch requires a secured backend, identity and access controls, property-scoped server authorization, encrypted backups and recovery, privacy/security review, and configured hosting, domain, and operational services.

## Run locally

Open `index.html` in a modern browser. To test installable-app features, serve this folder from a local web server (for example, `python -m http.server 8000`) and open `http://localhost:8000`.

## Publish the static demo

The checked-in Pages workflow deploys this folder from the repository's `main` branch after GitHub Pages is enabled with **GitHub Actions** as the build and deployment source. It can also be started manually from the Actions tab. The published `launch-config.js` starts a new browser with an empty workspace; it does not import, publish, or synchronize any browser's local data. The app remains public, local-browser-only demo software with no authentication or shared backend. Keep the noindex directive and demo-only notice unless the app is replaced with a production-ready, secured service.

## Business environments

Use the environment switcher to change between Property Management and Association Management. The app uses `#/property-management` and `#/association` hash routes so both environments work when hosted as a static site; these are not separate server paths. Property Management provides the rental portfolio and property, tenant, lease, and calendar views. Association Management provides association profiles, homeowner and board directories, ARC requests, assessments, association violations and common-area maintenance, reports, and its own calendar. Association-specific records and events are stored separately from rental operations in this browser, but this prototype does not provide server-side tenant isolation or authentication.

## Prototype limitations

- The sample residents and records are fictional. Changes, including contact and pet information, are saved in the current browser's local storage; there is no shared database, login, access control, or backup. Do not enter real resident personal information until a secure backend and access controls are in place.
- The unit record supports a primary tenant and additional household members, each with an occupation and individual pet details. Monthly recurring charge entries are added to the unit's current monthly ledger total. The browser-only prototype does not automatically generate future monthly billing cycles.
- A violation can be marked for "Termination review" for management follow-up. This does not terminate a tenancy or change the unit's occupancy status.
- The report library lists the requested financial, AR, leasing, property, maintenance, owner, vendor, resident, marketing, and portfolio reports. Reports supported by current data include property/unit directories and status, occupancy/vacancy, rent roll, AR balances/delinquency, collections, resident directory/payment history, work orders, community incidents, and property-level summaries. Filters apply by date, building, unit, and status where supported. Reports without required source records are listed but clearly marked unavailable; the app does not invent financial statements, leases, vendor, owner, marketing, or expense data. Export is available as CSV, Word-compatible `.doc` (HTML-based, not native `.docx`), and browser Print / Save PDF.
- Users & access provides eight built-in VHMS positions: President / Executive Director, Property Manager, Assistant Property Manager, Housing Administrator, Leasing / Occupancy Officer, Maintenance Technician, Accountant / Finance Officer, and Records Officer. Authorized President and Property Manager roles can manage accounts, assign multiple roles, and customize permissions or add custom roles. Assigned-role permissions are combined for the selected demo user. These are local prototype records and client-side UI gates only—not authentication or security controls. Role-based authorization, property/department data filtering, approvals separation, session security, account resets, backups, archival/recovery, and tamper-proof audit logging must be enforced by a secure backend before production use.
- Dashboard views can be assigned per role by the President / Executive Director in the role editor. Association dashboard widgets can also be selected per role. This is a client-side prototype control only.
- The property portfolio supports Building, Commercial, SFR, and MFR profiles, structured property/location/ownership/financial/leasing/vendor/document details, and customizable groups. Groups are organizational labels only. Each unit is assigned to one property, and unit lists, property summaries, and portfolio metrics use those property links so units from different properties do not mix.
- Authorized property managers can open Bulk Rent Update from Properties, Units & residents, or Accounting and set monthly base rent for one unit, selected units, or all units in a property, with building and occupancy filters and a before-apply preview. Occupied-unit rent changes update the current tenant charge while preserving payments; vacant-unit changes update the base rent only. This applies immediately and is recorded in the local audit trail; approval, rollback, resident notifications, and separate operating data for properties without linked units are not connected.
- Property managers can manually create portfolio records without importing a file, including property type, code, address, owner, manager, year built, description, and portfolio group. Open a property profile to add units manually, import units from CSV, or add a 36-unit building to an MFR property. The Units & residents directory has a property selector; building and unit numbers may repeat in different properties, but not within the same property. CSV imports require `building` and `unitNumber` columns and optionally accept `monthlyRent` and `status` (Vacant only); imports are validated before any records are saved. Each property supports up to 150 buildings with 36 units per building.
- Association profiles, homeowner and board entries, architectural requests, assessments, association violations, common-area maintenance tasks, and environment-specific calendar events can be entered in Association Management and persist locally in this browser. They do not create rental units or share an operating ledger with Property Management. HOA/COA profiles are managed in Association Management, not as rental portfolio entries. Calendar views and exports are local; Google/Outlook sync and map integrations are not configured.
- Universal search searches records visible to the selected demo role, including properties, units/residents, rent, receipts, work orders, incidents, reports, staff/roles, and property payment instructions. This is a local UI filter, not an access-control boundary.
- General Settings includes Company, User Management, Security, Leasing, Resident Portal, Accounting, AP & Bill Pay, Maintenance, Communications, Online Payments, Document Management, Website & Marketing, Owner Portal, Vendor, Reporting, Automation, Integrations, Custom Fields & Preferences, Transaction, and System Preferences categories. Category on/off values and notes are stored locally; they do not enable external services or change backend workflows.
- The clickable profile menu opens My Settings for the selected demo user and shows General Settings only to users with the corresponding management permission. Personal profile/preferences are saved separately per demo user in browser storage; theme, contrast, compact view, reduced motion, font size, and accent color affect this browser. Profile photos require an HTTPS URL. Password changes, MFA, connected accounts, sessions, tokens, calendar sync, and secure personal-data requests remain unavailable without an authentication backend.
- Maintenance personnel, technician performance, budgets, income/expense, inventory, procurement, security incidents, inspection/compliance, document, complaint/grievance, visitor, and asset reports are listed as unavailable because the prototype has no source records for them. Annual/monthly reporting is based on available ledger and activity data and is not an audited accounting statement. Role-based report access and export audit trails require authenticated backend services and are not implemented.
- Rent payments can be recorded manually and a receipt can be printed. Online checkout is deliberately not enabled because no payment processor has been selected or configured. Never put payment credentials in browser code.
- Property payment methods support one Bank, Cash, Escrow, and Other instruction set per property. President / Property Manager demo roles can enter instructions and toggle resident visibility. These are instructions only; the app does not receive, route, or verify payments. Confirm the recipient outside the app before enabling or paying.
- The tenant portal is a role-preview, not a secured tenant account.
- Portal invitations, staff role invitation links, and phone/email OTP sign-in are intentionally not enabled: this project has no authentication backend, configured email/SMS delivery provider, or confirmed HTTPS domain. A unique link stored in browser code would not provide secure, shareable, single-use access. Production setup needs server-generated single-use expiring invitations, server-verified short-lived OTPs with rate/attempt limits, secure sessions, role authorization, and delivery/audit handling.
- This is a responsive web app that can be installed from a compatible browser when hosted over HTTPS. It is not a native iOS or Android app.
- The initial property has 22 buildings. Add buildings from the unit directory as needed; each new building adds 36 vacant units, up to 150 buildings total.
- Notification preferences, email/SMS provider choices, reminder schedules, community activity drafts, and violation reference rules are prototype-only and stored in this browser. No notifications are sent or scheduled. Actual delivery requires a secured backend, a configured email/SMS provider, resident contact consent and preferences, and appropriate message/audit handling. Provider credentials must never be stored in frontend code.
- Maintenance thread posts, staff contact records, and shared-space requests are also browser-local demos. Thread role/name selection is not authentication; use real role-based accounts before sharing tenant or maintenance communications. Staff contact registration does not create login accounts or synchronize web and mobile devices.
- Tenants can request a multi-purpose hall, park, or another named space from the portal. Requests start pending; management reviews them in Space requests. Approved same-space requests cannot overlap by date and time in this prototype, but venue availability, policies, and bookings still need operational confirmation.

Before using with real residents or collecting money, add a secure backend, authentication and role permissions, audit logs, backups, privacy controls, and a server-side integration with a payment processor that supports the property's needs in the Philippines.
